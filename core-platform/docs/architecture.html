Patterns transverses

  • Service discovery par DNS — chaque service s'annonce en <service>.internal sur core-network ; aucune IP en dur.
  • Alias de compatibilité — redis.internal, vault.internal, idp.internal survivent aux remplacements Redis→Valkey, Vault→OpenBao, authentik→Casdoor : les apps ne voient pas le changement.
  • Multi-tenant par isolation de ressource — une ressource par app sur chaque brique : DB + user Postgres, bucket + clé S3, namespace Temporal, client OIDC, website Umami, clé virtuelle LLM, chemin secret/<app>/. La plateforme ne connaît aucune app par son nom.
  • Backing services 12-factor — config par variables d'environnement, logs sur stdout, health checks /health + /ready.
  • Self-service — chaque app se provisionne elle-même via son bootstrap.sh ; pas de ticket à l'équipe plateforme.
  • 100 % open source OSI — pas d'open-core : d'où Valkey, OpenBao, SeaweedFS et Casdoor plutôt que Redis, Vault, MinIO et authentik.
